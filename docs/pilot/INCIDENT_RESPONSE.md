## ขั้นตอน

### 1. ควบคุมเหตุ (ภายใน 1 ชั่วโมงหลังรู้)

| เหตุ | ทำทันที |
|---|---|
| บัญชีผู้ใช้ถูกใช้โดยคนอื่น / โทรศัพท์หาย | ปิดใช้งานบัญชี + "รีเซ็ตแอปยืนยันตัวตน" (ตัด session ทันที) |
| ไฟล์ถูกแชร์ออก | Drive → Share → ลบผู้ที่ไม่เกี่ยวข้อง/ปิดลิงก์ |
| ระบบถูกเข้าถึงในวงกว้าง | หยุดระบบชั่วคราว: ตั้ง Script Property `APP_MODE` เป็นค่าที่ไม่รองรับ (เช่น `STOPPED`) ระบบจะปฏิเสธทุกคำขอ; หรือปิด Worker ใน Cloudflare |
| กุญแจรั่ว | หมุนกุญแจที่รั่ว (ดู `ACCESS_POLICY.md` ข้อ 4) |
| บัญชีเจ้าของระบบ (Google/Cloudflare) ถูกเข้าถึง | เปลี่ยนรหัสผ่าน, ลงชื่อออกจากทุกอุปกรณ์, ตรวจ 2SV และรหัสกู้คืน |

### 2. เก็บหลักฐาน (อย่าลบอะไร)

- ส่งออกชีต `AuditLogs` และไฟล์ archive ของเดือนที่เกี่ยวข้อง
- D1: `npx wrangler d1 execute smart-ltc-security-demo --remote --command "SELECT * FROM security_events ORDER BY created_at DESC LIMIT 500" --json > evidence-security-events.json`
- Cloudflare → Workers → Logs; Apps Script → Executions; Google Account → Security → Recent activity
- จดเวลา ผู้พบ สิ่งที่เห็น และสิ่งที่ทำไปแล้ว ลงแบบบันทึกเหตุ

### 3. ประเมินและตัดสินใจแจ้ง (ภายใน 24 ชั่วโมง)

DPO และผู้อำนวยการประเมิน: ข้อมูลอะไร กี่ราย มีข้อมูลสุขภาพ/เลขบัตรหรือไม่ ข้อมูลถูกเข้ารหัสหรือไม่ ใครเข้าถึงได้ และความเสี่ยงต่อเจ้าของข้อมูล

- **แจ้ง สคส. ภายใน 72 ชั่วโมงนับแต่ทราบเหตุ** เว้นแต่ไม่มีความเสี่ยงที่จะกระทบสิทธิและเสรีภาพของบุคคล (พ.ร.บ. คุ้มครองข้อมูลส่วนบุคคล ม.37(4)) ข้อมูลสุขภาพมักถือว่ามีความเสี่ยง
- **แจ้งเจ้าของข้อมูล** โดยไม่ชักช้า ถ้ามีความเสี่ยงสูง พร้อมแนวทางเยียวยา
- แจ้งหน่วยงานต้นสังกัดตามระเบียบ [ระบุ]
- บันทึกเหตุผลการตัดสินใจไว้ แม้ตัดสินใจไม่แจ้ง

### 4. กู้คืนและปิดเหตุ

กู้ข้อมูลจาก backup ถ้าจำเป็น (`BACKUP_DR.md`) เปิดระบบเมื่อแก้สาเหตุแล้ว แล้วประชุมทบทวนภายใน 2 สัปดาห์ บันทึกบทเรียนและสิ่งที่ต้องแก้ พร้อมผู้รับผิดชอบและกำหนดเสร็จ
